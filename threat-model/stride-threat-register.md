# STRIDE Threat Register

| ID / STRIDE | Asset / flow | Threat scenario | Impact / risk | Mitigation | Validation evidence |
|---|---|---|---|---|---|
| T1 - Spoofing | Credentials / session cookie | Weak password regex and no session-ID regeneration let an attacker reuse or guess a session and impersonate a user. | Account takeover; unauthorised access to portfolio data. High. | Hash passwords with bcrypt, enforce a strong password policy, call req.session.regenerate() on login. | Manual: session.js:116,144; user-dao.js:25,61 |
| T2 - Tampering | Forms / rendered templates | CSRF middleware is disabled and Swig autoescape is false, so state-changing requests and injected markup are not constrained. | Unauthorised state changes or stored script execution. High. | Re-enable csurf and context-aware output encoding; keep autoescape on. | Manual: server.js:7,137; ZAP anti-CSRF/CSP alerts |
| T3 - Repudiation | Privileged benefit updates | Benefit changes are applied without a structured audit record tying action to user and time. | Changes cannot be attributed during incident review. Medium. | Add tamper-evident audit logging with user, action, timestamp and source IP. | Manual: benefits.js:35; error.js:7-8 |
| T4 - Information Disclosure | Config secrets / HTTP headers | Hardcoded cookie and crypto keys, full config console dump and X-Powered-By expose internal detail. | Session forgery, decryption and fingerprinting. High. | Move secrets to environment/secret store, remove config dump, enable helmet. | Manual: config/env/all.js:8-9; config.js:12-13; ZAP X-Powered-By alert |
| T5 - Denial of Service | Regex / external fetch paths | Super-linear regex and user-controlled outbound HTTP with no timeout can consume CPU or sockets. | Service slowdown or outage. Medium. | Replace nested quantifier regex and enforce timeouts, size limits and an allowlist for URLs. | SonarQube hotspot S5852 profile.js:59; manual research.js:15-16 |
| T6 - Elevation of Privilege | Benefits routes | isAdmin middleware exists but is not attached to /benefits GET or POST, so any logged-in user can update benefit data. | Privilege escalation and unauthorised data modification. High. | Attach isAdmin to both benefits routes and add server-side role checks in the DAO. | Manual: index.js:55-60 |
| T7 - Tampering | Allocation threshold query | A string threshold is interpolated into a MongoDB $where expression, enabling JavaScript injection into the query. | Unauthorised record read or modification. High. | Remove $where; use typed numeric comparisons with the MongoDB query API. | Manual: allocations-dao.js:78; SonarQube security hotspot |
| T8 - Information Disclosure | Redirect and research response | /learn redirects to an arbitrary query URL and /research writes a fetched remote body directly to the response. | Phishing, token leakage and server-side request forgery. Medium. | Validate redirects against an allowlist; restrict outbound hosts, schemes and response size. | Manual: index.js:72; research.js:15-25 |
